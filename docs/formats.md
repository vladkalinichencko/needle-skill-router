# Форматы источников

## Claude

Путь: `~/.claude/projects/<проект>/<session-id>.jsonl`. Один файл — один диалог, включая ответвления. Внутри — поток записей, у каждой свой `type`.

| тип записи | что несёт | как используется |
|---|---|---|
| `ai-title` | автоназвание диалога | заголовок в манифесте |
| `user` | `message.content` — блоки; `isSidechain`, `timestamp`, `cwd`, `sessionId` | граница хода, если есть текстовый блок |
| `assistant` | `message.content` — блоки `text`, `tool_use`, `thinking` | текст ответа и вызовы инструментов |
| `system`, `summary`, `mode`, `queue-operation` | служебное | пропускается |

Блоки содержимого:

- `text` — реплика. Служебные напоминания приходят отдельной пользовательской записью и не открывают новый ход, иначе реальный запрос терялся бы, а вызов навыка приклеивался к строке с датой.
- `tool_use` — вызов инструмента: `name`, `input`. Навык — это `name = "Skill"`, `input.skill` (имя), `input.args` (необязательные аргументы).
- `tool_result` — результат инструмента, отбрасывается.
- `isSidechain = true` — запись принадлежит сабагенту. Такие ходы сохраняются и помечаются, потому что их «запрос» — текст задачи от главного агента.

Один и тот же session-id встречается в разных каталогах проектов (копии сессий), поэтому файл диалога кладётся в подкаталог проекта, а не в плоский список.

## Codex

Путь: `~/.codex/sessions/<год>/<месяц>/<день>/rollout-<время>-<id>.jsonl`. Формат — поток событий, а не пары «запрос-ответ».

| тип | полезная нагрузка | как используется |
|---|---|---|
| `session_meta` | `id`, `cwd`, `timestamp` | метаданные диалога |
| `response_item` → `message` | `role` (`user`, `assistant`, `developer`), `content` | реплики; `developer` — инструкции, отбрасываются |
| `response_item` → `function_call` | `name`, `arguments` | вызовы инструментов |
| `response_item` → `function_call_output`, `reasoning` | результат и рассуждение | отбрасываются |
| `event_msg` | `user_message`, `agent_message`, `token_count` | дублируют реплики, не используются |

Навыка как инструмента в Codex нет: навык подтягивается чтением файла описания. Поэтому вызов восстанавливается по вызову инструмента, в аргументах которого есть путь, оканчивающийся на `SKILL.md`; имя навыка — имя каталога. Повторы внутри одного хода схлопываются: чтение файла кусками даёт несколько вызовов подряд.

Ограничение: чтение описания может быть справкой, а не вызовом. Отличить одно от другого по данным нельзя, поэтому такие метки помечены как эвристические и их доля в датасете известна.

## Правила нормализации

Сохраняется: текст пользователя, текст ассистента, имя и вход каждого вызова инструмента, метка сабагента, время, заголовок, рабочий каталог.

Отбрасывается: описания инструментов (они повторяются в каждом запросе и дают основной объём), системные промпты, результаты инструментов, блоки рассуждений, служебные напоминания о дате.

Обрезается: вход вызова инструмента длиннее четырёх тысяч символов — с сохранением начала и пометкой об обрезке; аргументы вызова навыка — до пятисот символов.

## Язык

Определяется по соотношению кириллицы и латиницы в реплике: только кириллица — русский, только латиница — английский, заметная доля обоих — смешанный. Текст не переводится и не чистится.
