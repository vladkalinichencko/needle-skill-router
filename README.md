# needle-router

Крошечная модель, которая по тексту запроса решает, какой навык агенту подтянуть. Меню навыков уезжает из контекста большой модели в 27-мегабайтный роутер: большая модель больше не держит описания навыков и не выбирает между ними.

## Откуда берутся данные

Два источника сессий, оба читаются только на чтение, оригиналы не изменяются:

- **Claude** — сессии в `~/.claude/projects`, по файлу на диалог, записи вида «пользователь / ассистент», вызов навыка лежит отдельным блоком инструмента `Skill` с именем навыка и необязательными аргументами.
- **Codex** — rollout-файлы в `~/.codex/sessions`, поток событий: метаданные сессии, сообщения, вызовы инструментов. Отдельного инструмента для навыков там нет, навык подтягивается чтением файла описания, поэтому вызов восстанавливается по команде, которая этот файл читает.

Инвентарь навыков — `~/.agents/skills`: 115 описаний после раскрытия симлинков на плагинные наборы. Симлинки раскрыты намеренно: половина навыков — ссылки в кеш плагинов, и без раскрытия они выпадали из инвентаря вместе со всеми своими вызовами.

## Как из сессий получается датасет

1. **Нормализация.** Каждый диалог переписывается в один формат: метаданные сессии плюс список ходов. Ход — реплика пользователя и всё, что ассистент сделал до следующей реплики: текст, вызовы инструментов, вызовы навыков. Сохраняются тексты дословно и входы вызовов; выбрасываются описания инструментов, системные промпты и результаты инструментов — они занимают основной объём и к задаче отношения не имеют.
2. **Изоляция ходов.** Каждый ход рассматривается отдельно, без предыдущих реплик. Это то, что просили, но у метода есть цена: часть реплик без контекста нечитаема («не, давай лучше продолжим»), таких в датасете заметная доля.
3. **Матчинг.** Имена вызовов приводятся к каноническим (снимается префикс плагина), сопоставляются с инвентарём по имени навыка и по имени папки. Всё, что не нашлось в инвентаре, не теряется — попадает в отчёт о несопоставленных вызовах.
4. **Разделение.** Ходы с вызванным навыком дают пары «запрос → навык», ходы без вызовов — отдельный файл отказов. Ходы, где вызван только навык вне инвентаря, не попадают ни туда, ни туда: разметка была бы догадкой.
5. **Формат обучения.** Пары собираются в строки для needle: запрос, набор схем навыков, ответы. В строку кладутся только те схемы, которые реально встречаются в датасете, — 53 вместо 115, иначе промпт раздувается. Схема на 53 инструмента занимает 2 793 токена, из них половина — описания.

| отказов | 13 831 |
| строк в формате обучения | 591: 464 в обучение, 72 в валидацию, 55 отброшено как не влезающие в 8192 токена |
| русских / смешанных / английских запросов | 5 484 / 2 765 / 6 213 |

Самый частый класс — `unslop` (406 вызовов), дальше `prose` (68), `session-resume` (56), `software-developer` (47), `innopolis-a100-queue` (40). Четыре десятых датасета — один класс, это придётся учитывать при обучении. Отброшенные длинные строки забрали 105 пар и два класса целиком (`swiftui_liquid_glass`, `huggingface_papers` — по одной паре каждый), поэтому в обучении 50 классов, а в валидации 16.

Отчёт EDA и графики лежат в `reports`: доля использования каждого навыка, доля затронутых ходов и диалогов, распределение длины диалогов, разбивка по источникам, языкам и сабагентам, отдельный график вызовов вне инвентаря.

## Быстрый старт

```
scripts/run.sh
```

Меню: обучение, сборка архива, оценка базовой модели, оценка обученного архива, пересборка данных из локальных сессий, графики. Скрипт печатает каждый шаг с номером: проверка окружения, установка зависимостей (JAX ~500 МБ), проверка бэкенда, подбор батча по объёму видеопамяти, обучение. При наличии карты ставит CUDA-сборку; если прогон не влезает в память, повторяет с вдвое меньшим батчем. Неинтерактивно: `run.sh train`, `run.sh build`, `run.sh eval models/router.cact`. Переменные: `BATCH`, `MAXLEN`, `EPOCHS`, `RANK`.

В репозитории лежат готовые данные: `data/processed/dataset.jsonl` (пары «запрос → навык»), `needle.jsonl` (строки для обучения), `train.jsonl` и `val.jsonl` (сплит по диалогам, сид 42), `dataset_summary.json`. Сырые диалоги, адаптеры и веса не коммитятся: первые содержат личную переписку, вторые качаются автоматически. Из запросов вырезаны строки, похожие на ключи и токены.

## Структура

```
data/raw/skills/        копия описаний навыков (115), в репозиторий не входит
data/raw/dialogues/     нормализованные диалоги, в репозиторий не входит
data/processed/         пары, отказы, сплит, строки для обучения, сводка
reports/                отчёт EDA и графики, генерируются
src/router/             сбор, нормализация, матчинг, EDA, инференс, оценка
scripts/run.sh          меню запуска
docs/                   форматы источников, план обучения, запуск на A100
```

## Чего в данных нет и почему

- **Вызовы навыков в Codex — эвристика.** Там навык не является инструментом, поэтому вызов восстановлен по чтению файла описания. Часть таких чтений — справка, а не вызов; это шум, и его доля неизвестна.
- **Часть вызовов вне инвентаря.** `research-buddy`, `artifact-design`, `dataviz`, `control-in-app-browser` и другие живут в плагинах и в `~/.agents/skills` отсутствуют. Они перечислены в отчёте, но классами не стали.
- **Сабагенты включены.** Их ходы помечены, но их «запрос» — это текст задачи от главного агента, а не реплика пользователя. Фильтр есть, включать или нет — решается на этапе обучения.
- **Язык не приводится к одному.** Русские и смешанные запросы остаются как есть, язык помечен полем в каждой строке, чтобы позже сравнить варианты обучения.
